# Merchant demo: decisions made along the way

Ammar's prompt won over `docs/MERCHANT-MOCK.md` where they differed (navy direction B instead of Nida's palette, owner side inside `/app`, not a separate app).

- **One store, one place id.** The owner's place lives in the same localStorage store as `/app` (`t6p_app_mock_v1`), with the fixed id `your-place`, so its place and redeem pages exist in the static export. Two tabs stay in sync through the storage event, so a visit confirmed in one shows up on the dashboard in the other.
- **The owner's place always runs "today".** The demo pretends today is Tuesday. If the owner picks days without Tuesday, the other places would say "Not running today", but the owner's place skips that check, so the redeem never dead-ends in a meeting. Pause, blackout dates and the uses limit still apply.
- **Staff confirm on the same phone.** Like Nida's demo, the code screen has her "For staff" panel and a Confirm button, because the phone is passed across the table. The dashboard also shows a waiting code with Confirm, for when two phones are used. The old Partner tab and "At the door" screen are gone (redirected to `/app/owner`).
- **Dashboard order:** Recent visits first, then Nida's four numbers, then "You control the offer". The visit landing is the moment the demo builds to, so it sits at the top. The numbers are under the heading "How a month could look", labelled "Sample month · illustrative numbers" and "Not real results".
- **Days on the dashboard can't drop below three.** In onboarding, fewer than three days blocks Next with a plain message. On the live dashboard, taking off a day that would leave two is refused with "Keep at least 3 days…", so a live offer never breaks the rule.
- **Offer wording by category.** Each category starts with a suggested line (restaurant "Second main, on us.", café "Second coffee, on us.", spa starts on the upgrade "A free upgrade on your treatment.", and so on). Switching category swaps the line only while it's still a suggestion. The longer detail line only shows while the owner keeps the suggested words, so it never contradicts what they typed. Alcohol words are refused with "Offers can't include alcohol…".
- **No photo, no placeholder.** Their colour with the first letter of the name, centred. Photos are resized to 900px in the browser and stored as a JPEG data URL.
- **No saving shown for the owner's place.** Demo places show "Save about $X"; the owner's place has no menu price, so that line is hidden rather than invented.
- **Categories:** restaurant, café, spa, studio, hotel restaurant or spa, experience. **Neighbourhoods:** the six launch ones plus "Elsewhere in Toronto", as buttons, so only the name and offer need the keyboard.
- **"New meeting" = full reset** (place, photo, visits, history), behind a "Start a new meeting?" confirm. Reset demo on My pass does the same.
- **Install and offline.** The manifest now opens on `/partners-demo` with scope `/`. The service worker is generated at build (`src/app/app-sw.js/route.ts`) from the place list: on install it saves every demo page plus the scripts, styles, fonts and photos they reference, then serves network first with the saved copy as fallback. It only handles `/app`, `/partners-demo`, `/_next`, `/demo` and the icons; the marketing site is untouched.
- **QR code** is drawn at build time (the `qrcode` package, no network at runtime) and points at `${site address}/owners`. On Netlify the site address is the site's main URL, so it's the `.netlify.app` preview until the6pass.ca moves over.
- **`/partners-demo`** reuses the `/app` layout (fonts, manifest, phone frame). Robots disallows it and it isn't in the sitemap; `noindex` comes from that layout.
- The start screen heading uses Nida's "Two go out. One pays for mains." and her "Preview · Mar 2027" tag.
